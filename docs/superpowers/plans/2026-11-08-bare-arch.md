# Bare Arch Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Omarchy with a plain Arch + Hyprland desktop built from Stow modules in this repo (`~/Work/arch-setup`, new), installable from a thin custom ISO.

**Architecture:** Each feature is one top-level Stow module (config + `packages.txt` + optional `install.sh`). `bootstrap.sh` installs a list of modules. A `theme-set` script renders one palette into per-format generated files that every config includes. A thin archiso image runs `archinstall` with a saved config, then clones this repo and runs `bootstrap.sh`. Everything is proven in a QEMU VM before the real machine is reinstalled.

**Tech Stack:** bash + bats (tests, following `trim/tests/`), Lua 5.4 (Hyprland config, tested with stand-alone `lua`), GNU Stow, archiso/archinstall, QEMU + OVMF.

**Spec:** `docs/superpowers/specs/2026-11-08-bare-arch-design.md`

## Global Constraints

- **Do not stow any new module onto the current (Omarchy) machine.** It would overwrite live `~/.config/hypr` etc. All runtime verification happens in the QEMU VM (Task 12). Unit tests run anywhere.
- Packages only from official repos, plus AUR: `paru-bin`, `grimblast-git`, `limine-snapper-sync`, `wiremix` and `bluetui` if not in official repos at build time. Nothing else from the AUR without asking Harry.
- No colour value (`#rrggbb`, `rgb(...)`, `rgba(...)`) in any file except `theme/.config/theme/palettes/*.toml`. Enforced by the lint test in Task 1.
- Generated theme output goes to `~/.config/theme/generated/`, never into the repo.
- Every script: `#!/usr/bin/env bash`, `set -euo pipefail`, `shellcheck` clean, installed to `~/.local/bin` via its module, covered by bats tests using fake commands on `PATH` that log calls to `$CALLS` (pattern: `~/Work/dotfiles/trim/tests/helpers.bash`, read-only reference).
- Locale `en_US.UTF-8`, console keymap `uk`, XKB layout `gb`.
- Terminal `foot`; browser `firefox`; editor `nvim` (`EDITOR`/`VISUAL`). No Chromium, no VS Code.
- Nothing may write to any disk other than the one the user picks in the installer. Other disks may only be mounted read-only.
- Commits: stage only files you touched (`git add -- <paths>`), never `git add -A`.
- `~/Work/dotfiles` (the old repo) is a read-only reference: never modify it. The Hyprland module is named **`hyprland/`**.
- Repo URL used by the installer: `https://github.com/HRusby/arch-setup.git`, branch `main`.

## Review Focus

1. **A second disk with Windows on it** (VM disk 2 with a dummy `EFI/Microsoft/Boot/bootmgfw.efi`): installer and boot setup must never write to it; Limine gets a Windows entry pointing at it. Tests in Tasks 10 and 11; checked in Task 12.
2. **`theme-set` run where tools aren't running or installed** (TTY, during bootstrap, before Waybar starts): it must still render every generated file and exit 0, skipping reloads. Test in Task 2.
3. **Update wrapper with no orphans, no network, or a failed snapshot**: `pacman -Qdtq` exits 1 when there are no orphans (must not abort); a failed snapshot or reflector run must stop before `pacman -Syu` with a clear message. Tests in Task 3.
4. **Re-running `bootstrap.sh`** on a machine where real files already sit at stow targets: must stop and list the conflicting paths, and only take them over with `--adopt`. Running it twice must be a no-op. Tests in Task 1.
5. **Recorder crashed or killed outside the script**: recording status comes from the running process, not a state file, so the bar indicator and toggle never get stuck. Test in Task 7.
